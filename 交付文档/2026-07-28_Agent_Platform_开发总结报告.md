# Agent Platform 当日研发与模型评测总结报告

报告日期：2026-07-28  
项目阶段：无硬件 PC 版 MVP、Web 演示与本地模型可行性验证  
报告用途：管理层进展汇报与下一阶段决策

## 一、结论摘要

今天已将 Agent Platform 从架构与提示词方案推进到可运行、可演示、可审计、可自动评测的 PC 版 MVP。系统已经具备统一任务流程、五类本地工具、端云模型切换、权限与数据分级、风险确认、知识库导入、Web 交互和固定评测集。

当前结论为：**项目具备继续推进价值，可进入“本地模型参数契约优化 + RK3588 实机验证准备”阶段，但尚不应按生产版本交付。**

关键判断如下：

- DeepSeek V4 Flash 的综合准确性更高，参数提取准确率为 96.0%。
- 本地 Qwen2.5-3B 的意图准确率达到 94.0%，证明 3B 模型可以承担受约束的本地意图识别和工具编排。
- Qwen 参数提取准确率只有 68.0%，问题集中在字段名、动作枚举、Windows 路径和文本操作映射，不能仅靠扩大模型参数解决。
- 当前工程中的权限、Schema 校验、R3 风险确认和确定性工具层是必要安全边界。模型负责理解和建议，工具层负责执行与审计。
- 下一步应先优化参数契约和确定性规则，再决定是否投入 Qwen2.5-7B 或模型微调。

## 二、今日完成范围

### 1. Agent 后端 MVP

完成了开发提示词中 F1-F8、T1-T5、I1-I3 对应的主要能力：

- 统一数据协议、任务状态机、会话持久化和异常恢复。
- Mock、DeepSeek 云端和 Ollama Qwen 的模型适配入口。
- 工具注册、JSON Schema 校验、超时、取消、幂等和执行回执。
- 角色权限、D0-D3 数据分级、脱敏、端云路由和离线队列。
- 审计链、FastAPI、REST、SSE 和 50 条固定中文评测集。
- 文件查找、知识库问答、提醒待办、短文本处理、会议纪要五类业务工具。

### 2. Web 演示界面

完成单文件响应式 Web 任务中心：

- 七阶段任务进度：接收、理解、校验、权限、路由、执行、交付。
- SSE 实时状态更新、任务取消和审计时间线。
- 候选文件选择、提醒时间补填、R3 删除全部提醒三类确认面板。
- 1920×1080 桌面和 375×812 手机视口实测无横向溢出、无控件遮挡、无页面控制台错误。
- 前端文件为 15,248 字节，满足 15KB 级单文件约束。

### 3. 知识库与演示数据

- 创建 7 份虚构企业演示文档，覆盖保修、请假、差旅、安全、设备、入职和会议室场景。
- 支持 `.txt`、`.md`、`.docx`，兼容 UTF-8、UTF-8 BOM 和 GB18030。
- 支持增量跳过和 `--force` 强制重建。
- 5 个典型问题均能命中正确来源，1 个无关问题正确返回“未找到相关信息”。
- 创建 3 份真实候选周报文件，用于确认流程演示，不允许模型虚构文件路径。

### 4. 确认与安全流程

- 模糊文件名必须从本地索引候选中选择。
- “提醒我明天开会”必须补充具体时间后执行。
- “删除全部提醒”动态提升为 R3，不可撤销，必须明确确认。
- 用户拒绝后任务变为 `cancelled`，审计链记录 `confirmation_rejected`。
- 文件真实打开默认关闭；高风险操作不允许由模型静默执行。

### 5. 模型对比评测自动化

完成一键 PowerShell 流程：

- 检查 50 条用例、DeepSeek 配置、Ollama 状态和 `qwen2.5:3b` 模型。
- 自动切换 `.env`、启动健康检查服务、运行两轮评测、停止进程并恢复默认配置。
- 处理数据库单进程锁、Windows 带空格路径、Ollama 冷启动和本地代理 502 问题。
- 支持 `-Resume` 复用结构完整的 50 条报告。
- 自动生成 JSON 原始报告和 Markdown 对比结论。

## 四、Qwen 失败原因判断

Qwen 的 16 条失败中，仅 3 条为意图或工具选择错误，另外 13 条为参数问题：

- 5 条将 `query` 输出成 `question` 或 `text`。
- 2 条知识查询被合理缩写，但因当前评测采用精确参数匹配而判错。
- 2 条 Windows 路径丢失盘符或格式损坏。
- 2 条提醒动作判断错误，其中“取消提醒 12”被识别为 `delete_all`，但被 R3 策略阻断并要求确认。
- 2 条“缩写/总结”被识别成 `polish` 而非 `summarize`。

这表明主要瓶颈不是“3B 模型完全无法理解”，而是**小模型指令遵循能力与当前宽松参数契约共同造成的结果**。当前 `arguments` 允许任意对象，所以错误字段仍能获得 100% 外层 Schema 合规率。

## 五、当前价值

- 已证明“本地轻量模型负责理解和编排、确定性工具负责执行、云模型负责复杂场景”的端云协同方案可落地。
- Web、确认和审计链使系统具备可向非研发人员演示的完整操作闭环。
- 固定评测集和一键模型对比脚本使后续模型、提示词、量化版本和硬件更换可以量化比较，不再依赖主观体验。
- D3 不持久化、D2 默认不上云、白名单文件操作和高风险确认，为后续接入真实数据提供了安全基础。

## 六、尚未完成与风险

1. 当前是 PC 无硬件验证，尚未在 RK3588 上验证首字延迟、内存、温升、并发和 UI 响应。
2. Qwen 参数提取准确率 68.0%，尚未达到稳定本地编排要求。
3. 评测对知识查询采用精确字符串匹配，包含少量“语义可用但被判失败”的情况。
4. 外层 Schema 未按意图区分参数字段，100% Schema 合规不能代表工具参数正确。
5. API 自身不包含账号系统，局域网或生产暴露前必须接入认证代理。
6. 文件打开默认禁用，外部天气连接器仍为 Mock，真实企业系统和实时数据尚未接入。
7. 当前目录不是 Git 仓库，变更缺少版本化 diff、分支和回滚记录。

## 七、下一阶段建议

### P0：先优化工程契约

- 将通用 `arguments` 改为按意图区分的严格 Schema，禁止错误字段。
- 增加针对 16 条失败模式的 few-shot 示例和反例。
- Windows 路径从原始文本确定性提取，不让模型重写。
- 按意图白名单执行 `question/text → query` 等参数归一化。
- 为提醒 `query/cancel/delete_all` 和文本 `summarize/polish` 增加确定性规则。
- 评测报告保存实际参数，并将“契约正确”和“语义等价”拆分评分。

建议验收门槛：意图准确率不低于 95%，参数提取不低于 90%，工具选择不低于 98%，高风险误路由必须 100% 被策略或确认流程拦截。

### P1：再比较模型规格

- 使用同一 50 条及扩充后的对抗集复测 Qwen2.5-3B-Instruct。
- 若工程优化后仍达不到门槛，再在 16GB 设备上比较量化 Qwen2.5-7B-Instruct。
- 不建议仅通过扩大模型参数替代 Schema、权限、校验和确认机制。

### P2：RK3588 实机验证

- 测量 TTFT、持续生成速度、峰值内存、温升、长时间稳定性和并发退化。
- 验证 8GB 串行原型与 16GB 标准配置的差异。
- 验证本地模型、知识库、SSE、前端渲染同时运行时的 UI 响应。

## 八、建议管理决策

建议批准进入下一阶段，但以“参数契约优化达到验收门槛”为进入 RK3588 正式适配的前置条件。硬件选型优先评估 16GB 版本，并保留 DeepSeek 云端回退；本地 3B 模型不承担未经校验的高风险写操作。
