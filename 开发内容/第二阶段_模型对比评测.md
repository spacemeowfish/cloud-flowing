# 第二阶段：DeepSeek vs Qwen2.5-3B 本地模型对比评测

> 自执行任务：无需人工介入，自动完成两轮评测并输出对比报告

将此提示词完整复制给 Codex，作为开发任务。

---

## 开发提示词

### 目标
使用项目已有的 `agent-platform evaluate` 命令和 50 条固定评测用例，分别对 DeepSeek V4 Flash（云端）和 Qwen2.5-3B（本地 Ollama）跑一轮完整评测，产出同一格式的两份 JSON 报告，并基于两份报告生成一份可读的 Markdown 对比总结。

### 判断标准

1. DeepSeek 评测完成，`evaluation/reports/deepseek.json` 包含全部 5 个维度的准确率和延迟分布
2. Qwen 评测完成，`evaluation/reports/qwen.json` 包含与 DeepSeek 相同结构的指标
3. `evaluation/reports/comparison.md` 对比报告包含：总表（两列并排对比）、分意图准确率对比、延迟分布对比、失败用例分析、结论与建议
4. 整个流程无需人工操作，脚本化自动完成（切换配置 → 启动服务 → 跑评测 → 生成报告）

### 证据要求

- 两份 JSON 报告文件均存在且包含非空的 `metrics` 和 `per_intent` 字段
- 对比报告中的数字与 JSON 源文件完全一致
- 如果某轮评测有失败用例，报告中需列出失败用例的 ID、输入文本和期望/实际意图

### 权限边界

- 不修改任何业务代码（agent_platform/ 下的 .py 文件）
- 可通过复制覆盖 `.env` 文件来切换模型配置
- 启动和停止服务通过脚本控制，不要求手动操作终端
- 评测期间 Ollama 必须已启动并监听 `localhost:11434`
- 如 Ollama 未启动或模型未拉取，脚本应清晰报错并退出，不静默失败

### 停止条件

- `comparison.md` 生成完毕
- 两份 JSON 报告文件均就位
- 报告中包含明确的结论陈述（「本地 Qwen 意图准确率 X%，云端 DeepSeek Y%，差距 Z%」）

### 完成边界

交付以下文件：
- `evaluation/reports/deepseek.json` — DeepSeek 评测结果
- `evaluation/reports/qwen.json` — Qwen 评测结果
- `evaluation/reports/comparison.md` — 对比分析报告
- `scripts/run_comparison.ps1` — 一键执行的 PowerShell 脚本（可选但推荐）

## 执行流程

```
1. 检查前置条件
   ├── Ollama 是否运行？如未运行则报错退出
   ├── qwen2.5:3b 模型是否已拉取？
   ├── .env.deepseek 和 .env.qwen 是否存在？
   └── 50 条评测用例是否就位？

2. DeepSeek 评测
   ├── copy .env.deepseek .env
   ├── 杀死旧服务进程
   ├── 启动 agent-platform serve（后台）
   ├── 等待服务就绪（GET /health 返回 200）
   ├── agent-platform evaluate --mode cloud --output evaluation/reports/deepseek.json
   ├── 杀死服务进程
   └── 验证 deepseek.json 非空

3. Qwen 评测
   ├── copy .env.qwen .env
   ├── 启动 agent-platform serve（后台）
   ├── 等待服务就绪
   ├── agent-platform evaluate --mode cloud --output evaluation/reports/qwen.json
   ├── 杀死服务进程
   └── 验证 qwen.json 非空

4. 生成对比报告
   ├── 读取两份 JSON
   ├── 计算差距
   ├── 标记异常指标（延迟 >5s、准确率 <80% 等）
   ├── 输出 comparison.md
   └── 恢复 .env.deepseek 为默认配置
```

## 注意事项

1. **Qwen 延迟预期**：本地 CPU 推理，P50 可能在 1-3 秒，P95 可能到 5-8 秒。这是正常的，报告中标注即可。
2. **JSON 格式稳定性**：Qwen 3B 可能出现非 JSON 输出。CloudAdapter 已有 `ModelError` 兜底，失败用例会自动记录。
3. **服务清理**：每次评测前必须杀掉旧进程，确保使用正确的 `.env` 配置启动。
4. **Ollama 内存**：Qwen 3B W8A8 约需 3GB 内存，确保系统有足够空闲内存。
5. **评测时间**：DeepSeek 约 1-2 分钟，Qwen 本地推理约 3-5 分钟。

## 代码审查提示词（质量）

检查项：
1. 脚本是否正确处理了 Ollama 未启动的情况（明确报错而非超时挂死）
2. 服务启动后的就绪检查是否足够健壮（重试 3 次，间隔 2 秒）
3. 两份 JSON 报告的结构是否一致（可直接做 diff）
4. 报告中的百分比是否精确到小数点后一位

---

## 代码审查提示词（性能）

检查项：
1. 评测脚本是否在每轮完成后立即杀死服务进程（不残留）
2. Ollama 是否在评测期间有资源泄漏（内存持续增长）
3. 失败用例的重试策略是否合理（评测不重试，记录原因即可）
