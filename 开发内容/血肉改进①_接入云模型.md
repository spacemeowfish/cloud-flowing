# 血肉改进 ①：接入真实云模型

> 改动量：1 行配置 + 可选 1 个适配器微调 | 与前端开发完全并行

将此提示词完整复制给 Codex，作为开发任务。

---

## 开发提示词

### 目标
激活已有的 CloudModelAdapter，使 Agent 在 `MODEL_PROVIDER=cloud` 时调用真实大模型（OpenAI-compatible 协议），替代 Mock 模型的规则匹配。不改架构，只改配置和必要的适配器兼容性修复。

### 判断标准

1. 设置 `MODEL_PROVIDER=cloud` 后，Agent 启动时自动使用 CloudAdapter
2. CloudAdapter 向配置的 `CLOUD_BASE_URL` 发送请求，携带 `CLOUD_API_KEY`
3. 模型返回的 JSON 被正确解析为 `IntentResult`（intent + arguments + missing_fields + confidence），与 MockAdapter 返回格式完全一致
4. 请求失败时（超时/限流/格式错误）抛出明确的 `ModelError`，不静默降级为 Mock
5. 支持通过 `CLOUD_MODEL` 环境变量指定模型名称

### 证据要求

- 使用一个真实 API Key 测试，发送「帮我润色这段话：项目下季度交付」→ 模型返回 `intent: text_polish` 或类似的结构化 JSON
- 模拟 API 返回非 JSON 内容 → CloudAdapter 抛出 `ModelError(retryable=False)`
- 模拟 API 返回 429 → CloudAdapter 抛出 `ModelError(retryable=True)`
- 验证 `.env.example` 中包含所有新增环境变量的说明

### 权限边界

- API Key 只从环境变量读取，不允许硬编码或写入配置文件
- 请求日志不记录 Authorization header 和完整请求体
- 不修改 MockAdapter 或 ModelGateway 的接口定义
- 不更改默认值：未设置环境变量时默认仍为 `mock`

### 停止条件

- `MODEL_PROVIDER=cloud` 启动后 health 端点显示 `model_provider: cloud`
- 发送一条中文请求 → 任务正常完成 → 审计日志显示 model_output 事件
- 模拟网络断开 → CloudAdapter 超时后抛出可重试错误
- `.env.example` 更新完毕

### 检索边界

查阅所选云服务商的 Chat Completions API 文档，确认 JSON mode 或 Structured Output 的启用方式。CloudAdapter 必须使用 `response_format: {"type": "json_object"}` 或等效参数，确保模型输出合法 JSON。

### 完成边界

需要改动的文件：`agent_platform/adapters/cloud_adapter.py`（如有 bug）、`.env.example`（新增变量说明）、`agent_platform/config/`（新增配置项）。不改动其他模块。

## 代码审查提示词（质量）

检查项：
1. CloudAdapter 的 `generate()` 方法是否正确构造了 system prompt（要求模型输出 JSON）
2. HTTP 错误映射是否正确：401/403 → 不可重试，429/502/503 → 可重试
3. 响应解析失败时，错误信息是否包含原始响应的前 200 字符（帮助调试）
4. API Key 是否在日志中完全不可见

---

## 代码审查提示词（性能）

检查项：
1. HTTP 连接池是否复用（httpx.AsyncClient 作为实例属性，不在每次请求时新建）
2. 请求超时设置是否合理（连接超时 10s，读取超时 30s）
3. 是否设置了 max_retries（httpx 内置重试 vs 业务层重试不重复）

---

## 代码审查提示词（复用性）

检查项：
1. CloudAdapter 的 prompt 模板是否可配置（system prompt 从配置/环境变量读取，不硬编码）
2. 响应解析逻辑是否独立于 HTTP 调用逻辑（方便后续切换到不同云服务商）
3. 是否预留了 `extra_headers` 和 `extra_body` 参数（兼容不同服务商的非标准参数）
