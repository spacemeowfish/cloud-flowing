## 开发提示词

### 目标
实现本地知识库问答工具。文档解析→文本切片→向量化→存储→检索→片段交给模型生成短答案→来源引用。无硬件阶段使用轻量 Embedding 模型（如 all-MiniLM-L6-v2 或更小的中文模型），向量存储使用 SQLite 或 ChromaDB。

### 判断标准

1. 支持 .txt / .md / .docx 文档导入
2. 切片策略：按段落 + 重叠窗口，单片段 200-500 token
3. 检索返回 Top-5 最相关片段，附带文档名和片段位置
4. 模型生成的答案必须引用来源片段，无可靠依据时返回"未找到相关信息"
5. 知识库更新后自动重建受影响文档的索引

### 证据要求

- 导入 3 篇测试文档（1 txt + 1 md + 1 docx），验证全部可检索
- 提问"X 产品的保修期是多少"（文档中有明确答案），验证答案正确且带来源
- 提问"Y 产品的价格"（文档中无此信息），验证返回"未找到相关信息"
- 更新一篇文档的内容后，重新提问验证新内容被检索到

### 权限边界

- 可导入的文档目录由配置白名单指定
- 不索引文件名包含 "password" "secret" "key" 的文档
- 检索返回的片段在交给模型前经过 F5 Data Classification 检查

### 停止条件

- 3 文档导入和检索测试通过
- 来源引用测试通过
- "无信息"拒绝回答测试通过
- 文档更新后索引刷新测试通过

### 完成边界

`tools/knowledge_base_tool.py`，依赖独立的 DocumentParser 和 VectorStore。向量模型配置在 `config/rag.yaml`。

## 代码审查提示词

**质量**：切片是否保持了段落完整性（不在句子中间切断）、检索的 top-k 是否可配置

**性能**：向量化是否批量处理（非逐片段调用）、检索延迟（< 200ms for 1000 片段）

**复用性**：DocumentParser 是否支持注册新的文档格式处理器
