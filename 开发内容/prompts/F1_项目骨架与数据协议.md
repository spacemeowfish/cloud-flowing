## 开发提示词

### 目标
搭建 Python 项目骨架，定义全部 Pydantic 数据模型和抽象接口（ABC），为所有后续模块提供统一的类型系统。不包括任何业务逻辑实现，只定义数据形状和接口契约。

### 判断标准

1. 所有数据模型使用 Pydantic v2 定义，字段类型完整、必填/可选明确
2. 所有抽象接口（ModelAdapter / Tool / Policy / Router 等）使用 ABC 定义，方法签名与架构文档一致
3. 配置管理支持环境变量和 .env 文件覆盖
4. 包结构清晰：`core/`（抽象接口）、`models/`（数据模型）、`config/`（配置）、`adapters/`（适配器占位）
5. `pip install -e .` 可安装，`pytest` 可运行（即使只有骨架测试）

### 证据要求

- 交付完整的目录结构和 `pyproject.toml`
- 每个 Pydantic model 有对应的单元测试验证序列化/反序列化
- 每个 ABC 接口有文档字符串说明契约
- 配置类支持从 `.env` 加载，并提供默认值

### 权限边界

- 只创建文件和目录，不执行任何系统命令或网络请求
- 不安装依赖（只声明在 pyproject.toml 中）
- 不引入任何具体模型调用代码

### 停止条件

- 运行 `python -c "from agent_platform.models import *; from agent_platform.core import *"` 无 ImportError
- 运行 `pytest` 全部通过（骨架测试数量 ≥ 数据模型数量）
- pyproject.toml 中 dependencies 列表完整

### 检索边界

搜索最新 Pydantic v2 和 ABC 用法时，仅验证 API 签名是否与最新稳定版一致，不引入未声明的第三方库。

### 行动边界

可直接创建目录和文件。不修改已有的架构文档.md。不确定的模型字段参考部署评估报告的数据结构和架构文档的模块定义。

### 完成边界

所有模型文件包含 `__all__` 导出列表。`pyproject.toml` 中包含 `[project.scripts]` 占位入口。`tests/` 下每个模型文件有对应测试。

## 代码审查提示词（质量）

审查 F1 代码，检查项：
1. Pydantic model 的 `Field` 是否全部显式声明了 `description` 和 `default`（或 `...` 标记必填）
2. ABC 接口方法签名是否与架构文档 §7 的模块职责一致
3. 是否存在循环导入
4. 类型注解覆盖率 100%，无 `Any` 滥用
5. 配置类是否对每个环境变量提供了默认值和类型转换

输出：逐条标注通过/问题，问题附具体文件和行号。

IDEA 自检：I 意图是确保接口契约与架构文档一致 / D 依据架构文档 §7 和部署评估报告 / E 不修改代码只出报告 / A 逐条检查结果标注严重程度

## 代码审查提示词（性能）

审查 F1 代码，检查项：
1. Pydantic model 是否存在可以替换为 `frozen=True` 的场景
2. 大规模列表字段是否使用了合适的默认工厂而非直接实例化
3. ABC 接口的 `@abstractmethod` 是否只标记了真正需要子类实现的方法
4. 配置加载是否避免了每次调用都重新解析 .env 文件

IDEA 自检：I 数据模型的错误模式在后期会放大 / D Pydantic v2 性能最佳实践 / E 标注为建议不阻断 / A 输出可优化项列表附量化估算

## 代码审查提示词（复用性）

审查 F1 代码，检查项：
1. 公共类型是否统一放在 `models/common.py` 而非散落在各模块
2. ABC 接口的粒度是否合适——每个接口职责单一
3. 配置 Schema 是否支持通过子类扩展
4. 错误类型是否定义了统一的异常层次结构
5. `__init__.py` 是否只导出公共 API，内部实现细节不暴露

IDEA 自检：I 骨架是后续所有模块的公共语言 / D 架构文档全部模块定义 / E 修改建议给出替代方案 / A 输出复用性评分 0-10 和改进清单
