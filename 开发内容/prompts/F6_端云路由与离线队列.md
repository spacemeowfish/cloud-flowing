## 开发提示词

### 目标
实现 Edge-Cloud Router（端云路由判定）、Offline Task Queue（离线任务队列）和 Resource Monitor（资源监控器）。Router 综合工具可用性、数据等级、资源水位和网络状态决定每个任务的执行端。Offline Queue 在断网时保存任务，恢复后继续执行。Resource Monitor 在无硬件阶段提供可配置的模拟实现。

### 判断标准

1. Router 的决策优先级：数据分级 > 工具可用性 > 资源水位 > 网络状态 > 用户偏好
2. 每次路由决策产出 RoutingDecision，包含：执行端、路由原因、出端数据摘要、替代方案
3. 离线队列：断网时任务自动入队，UI 显示"等待网络恢复"，恢复后按 FIFO 继续
4. 离线队列中的任务支持用户手动取消，取消后不再自动恢复
5. Resource Monitor 的三个模拟模式：正常（水位 40%）、高负载（水位 85% 触发转云）、降频（水位 90% 触发排队 + 转云）

### 证据要求

- Router 测试覆盖 6+ 种场景：本地有工具 + 低风险 / 本地无工具 / D2 数据不上云 / 高负载转云 / 断网 / 用户强制云端
- 离线队列测试：断网→入队→恢复→继续执行的完整流程
- 离线队列取消测试：入队后用户取消，恢复后不再执行
- Resource Monitor 的模拟模式切换测试：配置变更后路由决策改变

### 权限边界

- Router 不直接决策数据是否可以出端，必须调用 F5 DataClassificationService.check_outbound()
- Resource Monitor 的模拟值必须在配置文件中定义，不硬编码
- 离线队列不保存 D3 数据（在入队前由 F5 脱敏）

### 停止条件

- 6 种路由场景测试全部通过
- 离线队列 FIFO 顺序测试通过
- 离线队列恢复后幂等执行测试通过（使用 F4 的幂等键）
- Resource Monitor 的 3 种模式切换测试通过

### 完成边界

`core/edge_cloud_router.py`、`core/offline_queue.py`、`core/resource_monitor.py`，每个 150 行以内。依赖 F5 的 DataClassificationService 接口，但不依赖其具体实现（通过依赖注入）。

## 代码审查提示词（质量）

审查 F6 代码，检查项：
1. Router 的决策逻辑是否有明确的优先级和冲突解决规则
2. 离线队列的 SQLite 操作是否与 F3 的 Session Manager 使用同一连接（避免锁冲突）
3. 离线恢复后的幂等检查是否正确——如果任务在断网期间已被其他方式完成，不应重复执行
4. Resource Monitor 的模拟值变更是否会触发路由决策的重新评估

---

## 代码审查提示词（性能）

审查 F6 代码，检查项：
1. Router 的决策是否在 1ms 内完成（所有检查都是内存操作，无 I/O）
2. 离线队列的批量恢复是否使用单事务
3. 离线队列深度过大时（>1000）是否有告警机制

## 代码审查提示词（复用性）

审查 F6 代码，检查项：
1. Router 的策略是否可插拔（通过策略模式），允许后续增加新的决策因子
2. Resource Monitor 的接口是否清晰分离了「获取指标」和「做出判断」，后续真实硬件只需替换获取指标部分
3. 离线队列的存储是否与 F3 Session Manager 共享抽象层
