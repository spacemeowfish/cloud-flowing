## 开发提示词

### 目标
实现 Model Gateway 和两个适配器：MockModelAdapter（返回固定结构化 JSON，供测试用）和 CloudModelAdapter（调用当前云端模型 API）。确保上层代码只依赖 `ModelAdapter` 抽象接口，不感知具体模型实现。

### 判断标准

1. `ModelAdapter.generate()` 接口与架构文档一致：输入 messages + response_schema + max_tokens，输出 dict
2. 通过环境变量 `MODEL_PROVIDER` 切换适配器，默认 `mock`
3. MockAdapter 的响应结构完全符合架构文档的 JSON Schema（intent / arguments / missing_fields / confidence）
4. CloudAdapter 正确处理 API 超时、限流和格式错误，转换为统一的 ModelError
5. 每个适配器有独立的单元测试，MockAdapter 的测试覆盖所有预定义场景

### 证据要求

- `MockModelAdapter` 至少支持 5 种预定义意图（文件打开、知识查询、提醒创建、文本润色、会议纪要）
- `CloudModelAdapter` 的测试使用 VCR/mock HTTP 模式，不依赖真实 API Key
- 切换 `MODEL_PROVIDER` 后，同一个 Agent 调用无需修改任何代码
- `ModelError` 包含 `retryable: bool` 和 `detail: str`

### 权限边界

- CloudAdapter 的 API Key 从环境变量读取，不允许硬编码
- 不向云端发送任何模拟用户数据（测试只使用示例文本）
- 不在日志中记录完整的 API 请求/响应体（只记录元数据）

### 停止条件

- `python -m pytest tests/test_model_gateway.py -v` 全部通过
- MockAdapter 覆盖所有 5 种预定义意图
- CloudAdapter 正确处理超时（mock）、限流（429）、和格式错误（返回非 JSON）
- ModelGateway 的 `generate()` 方法签名与 F1 中的 ABC 一致

### 完成边界

交付文件清单：`core/model_gateway.py`、`adapters/mock_adapter.py`、`adapters/cloud_adapter.py`、`tests/test_model_gateway.py`。每个 Python 文件尾部有 `if __name__ == "__main__":` 的 smoke test。

## 代码审查提示词（质量）

审查 F2 代码，检查项：
1. MockAdapter 的响应是否每个字段都符合 Schema（不允许返回 Schema 未定义的字段）
2. CloudAdapter 的 HTTP 错误处理是否覆盖了：连接超时、读取超时、429 限流、500 服务端错误、返回非 JSON 内容
3. `ModelError` 的子类是否正确区分了可重试和不可重试错误
4. 异步调用是否正确使用了 `async/await` 和 `httpx.AsyncClient` 的上下文管理

IDEA：依据架构文档 §3 的接口定义和部署评估报告 §5 的端云任务链。出逐条检查结果。

## 代码审查提示词（性能）

审查 F2 代码，检查项：
1. CloudAdapter 的 HTTP 连接是否复用了连接池（不应每次调用新建连接）
2. MockAdapter 的响应生成是否有不必要的 I/O 或计算开销
3. `generate()` 方法的参数校验是否在异步路径之外完成

## 代码审查提示词（复用性）

审查 F2 代码，检查项：
1. 新增适配器是否只需实现 `ModelAdapter` 抽象接口的三个方法，不需要修改网关代码
2. 网关的错误转换逻辑是否独立于适配器实现
3. `response_schema` 的传递方式是否允许未来扩展
