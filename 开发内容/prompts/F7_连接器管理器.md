## 开发提示词

### 目标
实现 Connection Manager，统一管理外部 API 连接器的认证、速率限制、超时、重试、故障降级和数据质量校验。无硬件阶段至少实现一个模拟天气连接器和一个通用 HTTP 连接器基类。

### 判断标准

1. 连接器基类定义：认证方式、基础 URL、超时、速率限制（令牌桶）、重试策略（指数退避）、健康检查
2. 每个连接器注册时声明：数据等级、依赖的外部服务、降级策略（缓存/兜底值/明确失败）
3. 速率限制使用令牌桶算法，超限时排队或返回 429
4. 连接器故障时：3 次重试后进入降级模式，降级模式持续 30 秒后尝试恢复
5. 模拟天气连接器返回固定但合法的 JSON 结构

### 证据要求

- 令牌桶测试：突发 10 请求，验证速率限制生效
- 降级测试：模拟连接器故障 3 次后，验证降级策略生效
- 恢复测试：降级 30 秒后，下次请求尝试恢复
- 模拟天气连接器返回的数据通过 Schema 校验

### 权限边界

- 外部 API 的认证凭据从环境变量或加密配置读取，不硬编码
- 连接器的请求日志不记录完整 URL（包含 API Key 的 query string）和 Authorization header
- 连接器返回的数据在交给上层前通过 Data Classification 检查

### 停止条件

- 令牌桶速率限制测试通过
- 降级 + 恢复测试通过
- 模拟天气连接器可独立运行并返回有效数据
- 通用的 HTTP 连接器基类可用于后续快速开发新连接器

### 完成边界

`core/connection_manager.py`、`adapters/weather_connector.py`、`adapters/base_http_connector.py`。连接器配置存储在 `config/connectors.yaml`。

## 代码审查提示词（质量）

审查 F7 代码，检查项：
1. 令牌桶的实现是否线程/协程安全（多协程同时请求时计数不丢失）
2. 降级恢复的 30 秒计时器是否正确（使用 monotonic clock）
3. 连接器的请求重试是否区分了可重试错误（5xx）和不可重试错误（4xx 非 429）
4. 连接器返回的数据是否在上层使用前经过了 Schema 校验

---

## 代码审查提示词（性能）

审查 F7 代码，检查项：
1. 令牌桶的重填是否使用了惰性计算（请求时才计算，而非后台定时器）
2. 连接器实例是否可复用，每次请求不重新建立连接
3. 降级状态是否用原子变量标记（避免锁竞争）

---

## 代码审查提示词（复用性）

审查 F7 代码，检查项：
1. 新增连接器是否只需实现基类的 3 个方法（authenticate / request / health_check）
2. 速率限制和降级逻辑是否在基类中统一实现，不分散在各连接器
3. 连接器配置是否完全外部化（YAML），支持不同环境的配置覆盖
