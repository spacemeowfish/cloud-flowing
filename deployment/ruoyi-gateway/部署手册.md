# 若依认证网关：板端部署手册（RUOYI-AUTH-GATEWAY-001 Phase 6）

面向不懂原理的执行者。从头到尾照着做，遇到报错看第 8 节"常见问题"，解决不了再找开发者远程支援（计划第 8 节问题 11 的分工）。

**目标效果**：公网用户用浏览器打开 `https://<你的公网IP>` 看到若依登录页；登录后进入云湃 AI 操作台；所有流量强制 HTTPS；未登录访问任何业务接口都是 401；板子上只有 443 一个口对公网。

## 0. 准备清单

| # | 物品 | 说明 |
|---|---|---|
| 1 | RK3588 板子 | 刷好 Ubuntu 24.04（aarch64）或同类系统，能 SSH 登录 |
| 2 | 网络 | 板子已联网（能 `ping baidu.com`）；知道板子的内网 IP |
| 3 | 公网 IP | 从路由器后台/运营商处确认（动态 IP 见第 7 节 DDNS 预留） |
| 4 | 部署包 | `ruoyi-gateway-bundle.tar.gz`（由开发者打包，或你按第 1 节自己打） |
| 5 | 密码记录 | 纸笔或密码管理器，用于记录新设的密码 |

## 1. （开发机）打包部署包

> 如果开发者已经把 `ruoyi-gateway-bundle.tar.gz` 发给你，跳过本节。

在 Windows 开发机（已装好 `D:\ruoyi-env` 与仓库）：

```powershell
cd /d "D:\my new work\cloud-flowing_0806"
.\.venv\Scripts\python.exe deployment/ruoyi-gateway/pack_deploy.py
```

产物在 `deployment\ruoyi-gateway\dist\ruoyi-gateway-bundle.tar.gz`。打包脚本会自动核对 jar / SQL / 前端 dist 是否齐全，缺什么会报错。

## 2. 把部署包传到板子

在开发机 PowerShell（把 IP 换成板子内网 IP，如 192.168.1.50）：

```powershell
scp deployment\ruoyi-gateway\dist\ruoyi-gateway-bundle.tar.gz ubuntu@192.168.1.50:/home/ubuntu/
```

在板子上解压并进入目录：

```bash
tar -xzf ~/ruoyi-gateway-bundle.tar.gz
cd ruoyi-gateway-bundle
ls   # 应看到 install.sh、nginx、systemd、tls、ruoyi、ruoyi-ui、agent-platform、docs
```

## 3. 一键安装

```bash
sudo bash install.sh <你的公网IP>
```

例如公网 IP 是 123.45.67.89：`sudo bash install.sh 123.45.67.89`。

脚本自动完成：装 JDK17/MySQL/Redis/nginx/openssl/Python → 生成强随机密钥（存 `/etc/ruoyi-gateway/env`，权限 600）→ 建库 `ry-vue` 导入若依数据 → MySQL/Redis 只监听 127.0.0.1 → 部署若依后端、前端、云湃 AI 操作台 → 生成自签证书（绑你的公网 IP）→ 装好三个 systemd 服务并启动 → 自动清空"普通角色"的若依菜单权限（生产加固）。

耗时约 5～15 分钟（主要在装包和 Python 依赖）。中途卡住/报错看第 8 节。

**注意**：脚本不会自动启用防火墙（怕把远程 SSH 锁死），这是刻意设计，第 7 节手动做。

## 4. 路由器端口映射（板子在路由器后面的情况）

> 板子直接插公网网线（有独立公网 IP）可跳过本节。

登录路由器后台 → 找"端口映射/端口转发/虚拟服务器"：

- 外部端口 `443` → 内部地址 `板子内网IP` → 内部端口 `443`（TCP）
- **家宽 80/443 被封**（常见）：改用非常规端口，如外部端口 `8443` → 内部 `8443`；同时把板子上 `/etc/nginx/nginx.conf` 里的 `listen 443 ssl` 改成 `listen 8443 ssl`（文件里有中文注释标了位置），然后：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

之后访问地址是 `https://<公网IP>:8443`。

## 5. 首次登录与账号建设（重要）

1. 浏览器打开 `https://<公网IP>`（或带端口）→ 自签证书警告是**预期现象**，点"高级 → 继续访问"（计划第 8 节问题 10 已接受）。
2. 用 `admin` / `admin123` 登录 → 系统会提示改密码 → **立刻改成强密码并记下**。
3. 建角色：系统管理 → 角色管理 → 新增：
   - 角色名称 `developer`，**权限字符（roleKey）必须填 `developer`**（这是开发者控制台的开关，一字不能差）；
   - 角色顺序随意；菜单权限可以不勾（开发者用的是 `/agent-api/` 操作台，与若依菜单无关）。
4. 建账号：系统管理 → 用户管理 → 新增，每人一个账号（**不开放注册**，公网下只能手动建）：
   - 普通员工 → 分配"普通角色"（该角色的菜单权限安装时已清空，登录后只看到首页，安全）。
   - 开发/管理员 → 分配 `developer` 角色。
5. 记住：账号密码存在若依；云湃 AI 不存密码，数据按账号隔离（同一账号跨设备数据跟随）。

## 6. 快速自测（部署人版）

- 打开 `https://<公网IP>/agent-api/` → 弹出"需要登录后使用" → 登录任一账号 → 自动进入操作台。
- 普通账号：页脚没有"开发者控制台"；developer 账号：有，且能打开（8 工具 / 24 接口）。
- 提交一条任务（如"添加待办 测试部署 高优先级"）→ 走到"已完成"出卡片。
- 登出后回到登录页。
- 完整版按 `docs/tasks/2026-08-21-ruoyi-gateway-test-guide.md`（仓库内）与《安全验收清单》逐条过。

## 7. 防火墙（必做，做完才算部署完成）

在板子上执行（**顺序不能乱**：先放行，最后才 enable）：

```bash
sudo ufw allow 443/tcp                 # 家宽封 443 且用 8443 时改成 sudo ufw allow 8443/tcp
sudo ufw allow from 192.168.1.0/24 to any port 22   # 只允许内网网段 SSH（按你的网段改）
sudo ufw status verbose                # 确认上面两条已在列表里
sudo ufw enable                        # 确认后启用
```

启用后再开一个 SSH 连接测试能不能连（别关当前窗口直到验证成功）。

**DDNS 预留**：若公网 IP 是动态的（每次拨号会变），在路由器 DDNS 功能里绑定一个域名，访问地址改用该域名（部署期由老板确认，计划第 8 节问题 1）。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| `nginx -t` 报证书文件不存在 | 证书没生成：`sudo bash tls/gen-self-signed.sh <公网IP>` 后重跑安装 |
| 若依页能开但操作台 502 | `journalctl -u agent-platform -e` 看日志；多半是 `/etc/ruoyi-gateway/env` 的密钥与若依不一致，重跑 install.sh 后 `sudo systemctl restart ruoyi agent-platform` |
| 登录报 500"用户已封禁" | 账号被停用：admin 在用户管理里把状态切回"正常" |
| MySQL 服务名不同（mariadb） | 安装脚本已自动识别；确认 `systemctl status mariadb` |
| 密码输错 5 次被锁 10 分钟 | 若依内置防爆破（maxRetryCount=5 / lockTime=10），等 10 分钟或让 admin 改密 |
| 浏览器一直"不安全"红色警告 | 自签证书的预期表现；如介意可后续换正规证书（不在本包范围） |
| 忘记所有密码 | `D:\ruoyi-env` 侧开发者可查部署记录；板上密钥在 `/etc/ruoyi-gateway/env` |

## 9. 日常运维速查

```bash
systemctl status ruoyi agent-platform nginx     # 看状态
journalctl -u ruoyi -e                          # 若依日志
journalctl -u agent-platform -e                 # 操作台日志
tail -f /var/log/nginx/access.log               # 访问日志
sudo systemctl restart ruoyi agent-platform     # 改密钥/配置后重启
sudo nginx -t && sudo systemctl reload nginx    # 改 nginx 配置后热载
```

重启板子后三个服务（mysql/redis/ruoyi/agent-platform/nginx）都会自动恢复（已 enable），开机自启验证属 Phase 7 验收项。
