# 云湃 Agent RK3588 双模型 PoC 使用说明

## 1. 用途和限制

本交付用于验证“本地模型 + Agent + Web 操作台”能否在 8 GB RK3588 设备上运行。包含两个独立的 ARM64 CPU 镜像：

- Qwen2.5-3B-Instruct Q4_K_M：能力较强，资源占用较高。
- LFM2.5-1.2B-Instruct Q4_K_M：体积较小，适合先验证设备和流程。

两个模型必须串行运行，一次只启动一个。本版不包含声卡、ASR、TTS、扬声器或 NPU 加速，不能作为量产性能结论。

## 2. 设备要求

- RK3588，Linux ARM64；`uname -m` 应返回 `aarch64` 或 `arm64`。
- 8 GB 内存。
- 已安装 Docker，当前用户可以执行 `docker info`。
- 已安装 Python 3。
- 若同时携带两份 tar 并导入两个镜像，建议至少预留 10 GB 可用磁盘。
- 测试期间保持稳定供电和散热，不要并行运行其他大模型。

上板后先执行：

```sh
uname -m
docker version
docker info
python3 --version
free -h
df -h
```

## 3. 交付目录

请把对应的单模型目录完整放到设备，不要只复制 tar。Qwen 包目录为 `rk3588-qwen`，LFM 包目录为 `rk3588-lfm`；每个包只包含自己的模型 tar 和单行校验清单。

Qwen 包包含：

```text
cloud-flowing-qwen-rk3588-cpu-poc.tar
SHA256SUMS
install.sh
board_probe.sh
benchmark_profiles.py
README.md
RK3588-使用说明.md
```

LFM 包的公共文件相同，模型文件替换为：

```text
cloud-flowing-lfm-rk3588-cpu-poc.tar
```

进入该目录后执行：

```sh
chmod +x install.sh board_probe.sh
sha256sum -c SHA256SUMS
```

两项均显示 `OK` 后再继续。如果校验失败，重新复制对应 tar，不要强行导入。

## 4. 首次快速启动

建议先用 LFM 验证设备。以下方式只使用保守启动档，不执行完整性能对照：

```sh
docker load --input ./cloud-flowing-lfm-rk3588-cpu-poc.tar
docker rm --force cloud-flowing-poc 2>/dev/null || true
docker run --detach \
  --name cloud-flowing-poc \
  --restart unless-stopped \
  --publish 127.0.0.1:8000:8000 \
  --env LLAMACPP_THREADS=4 \
  --env LLAMACPP_CONTEXT_SIZE=2048 \
  --env LLAMACPP_MAX_TOKENS=256 \
  --env LLAMACPP_BATCH_SIZE=256 \
  --env LLAMACPP_PARALLEL=1 \
  --volume cloud-flowing-poc-data:/opt/app/data \
  --volume cloud-flowing-poc-logs:/opt/app/logs \
  cloud-flowing-lfm2.5-1.2b:rk3588-cpu-poc
```

检查启动状态：

```sh
docker logs --follow cloud-flowing-poc
```

出现 `Application startup complete` 后按 `Ctrl+C` 退出日志查看，容器不会停止。再执行：

```sh
curl http://127.0.0.1:8000/health
```

返回内容包含 `"status":"ok"` 和 `"model_provider":"llamacpp"` 即表示“模型 + Agent”已经启动。

Qwen 快速启动时，把上述 tar、镜像名分别替换为：

```text
cloud-flowing-qwen-rk3588-cpu-poc.tar
cloud-flowing-qwen2.5-3b:rk3588-cpu-poc
```

## 5. 从电脑访问操作台

默认端口只绑定设备本机，推荐在电脑上建立 SSH 隧道：

```sh
ssh -L 8000:127.0.0.1:8000 用户名@设备IP
```

保持 SSH 窗口打开，在电脑浏览器访问：

```text
http://127.0.0.1:8000
```

容器内 Agent 不再要求密码环境变量（旧"开发者密码门"已随 ADR 0007 退役，认证由若依网关承担，见 `deployment/ruoyi-gateway/`）。

如果设备位于可信、隔离的局域网，也可以在启动时把端口参数改为：

```sh
--publish 0.0.0.0:8000:8000
```

然后访问 `http://设备IP:8000`。不要把 8000 端口直接暴露到公网。

## 6. 完整自动性能测试

首次快速启动通过后，再运行自动测试。脚本会依次执行启动档、4/6/8 线程性能档和压力档，期间会多次重建测试容器，耗时可能达到几十分钟或更久。

测试 Qwen：

```sh
sh install.sh qwen ./cloud-flowing-qwen-rk3588-cpu-poc.tar
```

测试 LFM：

```sh
sh install.sh lfm ./cloud-flowing-lfm-rk3588-cpu-poc.tar
```

首次只想跳过 8192 上下文压力档时：

```sh
sh install.sh lfm ./cloud-flowing-lfm-rk3588-cpu-poc.tar --skip-pressure
```

默认仍只允许设备本机访问。可信局域网直接访问时：

```sh
POC_BIND_ADDRESS=0.0.0.0 sh install.sh lfm ./cloud-flowing-lfm-rk3588-cpu-poc.tar --skip-pressure
```

脚本完成后会保留最佳配置容器 `cloud-flowing-poc`，并生成：

- `board-probe.txt`：系统、CPU、内存、磁盘、Docker 和温度探测。
- `benchmark-report.json`：加载时间、TTFT、Tokens/s、峰值资源和连续请求结果。
- `selected.env`：该设备选出的最终运行参数。

文件位于当前目录下新建的 `rk3588-results-模型-时间` 目录。

## 7. 常用管理命令

```sh
# 查看运行状态
docker ps --filter name=cloud-flowing-poc

# 查看日志
docker logs --tail 200 cloud-flowing-poc

# 实时查看资源占用
docker stats cloud-flowing-poc

# 停止
docker stop cloud-flowing-poc

# 再次启动
docker start cloud-flowing-poc

# 重启
docker restart cloud-flowing-poc
```

切换模型时直接运行另一模型的 `install.sh`。脚本会替换同名容器，但保留 `cloud-flowing-poc-data` 和 `cloud-flowing-poc-logs` 数据卷。

## 8. 常见问题

### 提示 `This package is for ARM64`

设备不是 ARM64，或运行位置不是 RK3588 系统。检查 `uname -m`。

### 提示 `SHA256 mismatch`

镜像包复制不完整或已损坏。重新传输 tar，并再次运行 `sha256sum -c SHA256SUMS`。

### 容器启动失败

```sh
docker ps -a --filter name=cloud-flowing-poc
docker logs --tail 300 cloud-flowing-poc
```

同时检查 8000 端口和剩余资源：

```sh
ss -lntp | grep ':8000'
free -h
df -h
```

### 出现 OOM、系统明显卡顿或温度过高

先停止测试，优先使用 LFM 和 2048 启动档。不要同时启动两个模型。4096 不稳定时才退回 2048，8192 只用于压力测试。

### 电脑无法打开操作台

默认仅监听设备的 `127.0.0.1`。使用 SSH 隧道，或在可信局域网中按第 5、6 节显式启用 `0.0.0.0`。

## 9. 清理说明

删除容器不会删除 Agent 数据：

```sh
docker rm --force cloud-flowing-poc
```

只有确认不再需要任务、日志和测试数据时，才删除数据卷：

```sh
docker volume rm cloud-flowing-poc-data cloud-flowing-poc-logs
```

删除数据卷不可恢复，请先备份 `rk3588-results-*` 结果目录。
