# ADR 0004: ZipVoice 作为任务输出适配器接入

- 状态：Accepted
- 日期：2026-08-12

## 背景

ZipVoice 的职责是把 Agent 已生成的文本转换为音频。如果把它注册为第九个意图工具，小模型需要额外区分“执行业务任务”和“朗读结果”，并且每个业务工具仍需单独决定何时发声。当前目标是让所有已有文本能力共用同一条 TTS 链路。

## 决策

1. ZipVoice 实现 `SpeechSynthesizer`，位于业务工具和模型 Provider 之外。
2. TTS API 以已完成任务为输入，从任务收据中提取最终可见文本，不重新调用 Agent 或大模型。
3. Web 操作台在用户点击播放时才生成音频；重新生成创建新版本，停止只控制浏览器中的单一播放器。
4. ZipVoice 资源通过环境变量引用外部目录。TTS 依赖为可选安装项，默认镜像和纯文本部署不携带模型或推理库。
5. ZipVoice 推理在进程内复用一次加载的模型，并用单并发锁保护 CPU 和内存。

## 后果

- 八个 Agent 工具的意图空间、风险和审计契约保持不变。
- 本机可以直接生成并由浏览器播放 WAV；无声卡的交换机也可把音频返回给远端浏览器。
- 进程首次合成需要加载约 180 MB 的 ONNX 权重，首播延迟会高于后续播放。
- `sherpa-onnx` 的 Linux ARM64 可用性与 RK3588 上的实际 RTF、峰值内存和温度仍需真机验收。
