# Agent Platform 操作台使用手册

## 1. 启动与访问

所有人必须先通过若依（RuoYi）统一登录才能使用操作台（`RUOYI-AUTH-GATEWAY-001`，ADR 0008）。本地推荐走"若依前端同源入口"：

```powershell
# 1. 启动若依本地栈（MySQL 3306 / Redis 6379 / 后端 8080 / 前端 8081）
D:\ruoyi-env\start-env.cmd
# 2. 在项目根目录启动 agent_platform（.env 已配置 RUOYI_JWT_SECRET / RUOYI_REDIS_URL）
Set-Location 'D:\my new work\cloud-flowing_0806'
.\.venv\Scripts\python.exe -m agent_platform.cli serve
# 3. 浏览器只访问同源入口
http://localhost:8081/agent-api/
```

- 操作台（普通用户任务页）：`http://localhost:8081/agent-api/`
- 开发者控制台（developer/admin 角色）：`http://localhost:8081/agent-api/developer`
- Swagger API 文档（开发者）：`http://localhost:8081/agent-api/docs`
- OpenAPI JSON（开发者）：`http://localhost:8081/agent-api/openapi.json`
- 服务健康（匿名白名单）：`http://localhost:8081/agent-api/health`

若依前端 dev 服务器的 `vue.config.js` 已配置 `/agent-api` 代理转发到 `http://127.0.0.1:8000`（可用 `AGENT_API_TARGET` 覆盖），使操作台与若依登录页同源、共享 `Admin-Token` cookie。

也可以用 `desktop` 监督模式直接启动工作台（`http://localhost:8000/`）。此时操作台不在若依同源，需在 `.env` 额外配置 `RUOYI_LOGIN_URL=http://localhost:8081/#/login` 与 `RUOYI_LOGOUT_URL=/dev-api/logout`：登录弹窗会打开若依登录页，登录后操作台自动继续（cookie 按 host 共享，仍限于本机回环）。`serve` 与 `desktop` 均默认只监听回环地址。

### 登录、角色与登出

- 未持有效令牌打开操作台时，页面被"需要登录"闸机拦住；点击"打开若依登录页"完成登录（含验证码）后本页自动继续。
- 令牌来自若依签发的 JWT（cookie `Admin-Token`），所有 API 请求由页面统一附加 `Authorization: Bearer`；令牌在若依侧被强退/删除会话后，操作台立即回到登录闸机。
- 角色决定界面：`普通用户角色` 只见任务页，页脚没有开发者入口，直接访问 `/developer` 会被重定向回任务页；`developer` 或 `admin` 角色页脚显示"开发者控制台"入口。
- 点击右上角"退出"：先调用若依登出接口吊销服务端会话，再清除本地令牌并回到若依登录页。

## 2. 页面说明

根页面只保留通用任务输入、真实阶段进度、确认/取消、结果和近期任务。下表页面均位于登录后的开发者控制台：

| 页面 | 主要用途 | 可测试子功能 |
|---|---|---|
| 总览 | 查看运行态、能力数、接口数、安全基线 | 8 工具清单、七阶段执行链、运行配置 |
| 通用任务 | 用自然语言测试意图路由 | 意图识别、参数补全、分级、风险、端云路由、审计 |
| 知识库问答 | 查询授权文档并核对来源 | TXT/MD/DOCX、增量索引、召回、引用、脱敏 |
| 文件查找 | 查找文件并从候选中选择 | 模糊搜索、排序、路径摘要、确认打开 |
| 提醒管理 | 管理本地提醒 | 创建、未来/过期查询、取消、完成、清空全部 |
| 待办事项 | 管理带 ID 的个人任务 | 创建、组合筛选、更新、完成、删除、标签、截止时间 |
| 日程管理 | 管理一次性或重复日程 | 创建、范围查询、重复规则、提前通知、取消 |
| 文本处理 | 生成但不发送文本 | 润色、总结、语气调整、草拟、事实保护 |
| 会议纪要 | 从授权文稿生成 Markdown 纪要 | 路径校验、脱敏、结构提取、可追溯输出 |
| 接口测试中心 | 验证 HTTP 接口完整性 | OpenAPI 清单、只读体检、自定义 GET/POST、工具 Schema |
| 任务历史 | 回看当前会话任务 | 状态筛选、响应 JSON、工具契约、审计链 |
| 最近日志 | 手动查看内存脱敏日志 | 时间、级别、模块、消息；最多 200 条 |
| 设置 | 管理本机运行配置 | Ollama 模型、授权目录、知识索引、ZipVoice、麦克风、自动重启 |

## 3. 推荐验收流程

1. 在“总览”确认显示 `8 tools`，并确认 HTTP 操作数与当前 OpenAPI 一致。
2. 进入“接口测试中心”，点击“运行只读体检”，确认四项检查均返回 HTTP 200。
3. 进入“知识库问答”，查询“产品保修期是多久？”，确认任务完成并显示来源文件和分块。
4. 进入“文件查找”，查询“项目周报”，确认出现候选选择页；拒绝或选择一个候选继续。
5. 进入“提醒管理”，选择“清空全部”并提交，确认任务停在 R3 人工确认；点击“拒绝”。
6. 打开右侧检查器的“审计”页，确认存在 `confirmation_rejected` 和 `task_cancelled`。
7. 进入“任务历史”，确认上述任务均可见且其他会话的数据不可见。

## 4. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tasks` | 创建异步任务 |
| GET | `/tasks?limit=50` | 当前会话任务列表 |
| GET | `/tasks/{task_id}` | 单任务状态与结果 |
| POST | `/tasks/{task_id}/confirm` | 批准、补参或选择候选 |
| POST | `/tasks/{task_id}/cancel` | 取消任务 |
| GET | `/tasks/{task_id}/audit` | 当前任务脱敏审计链 |
| GET | `/tasks/{task_id}/events` | SSE 实时状态流 |
| POST | `/tasks/{task_id}/speech` | 为已完成任务生成新的 ZipVoice WAV 版本 |
| GET | `/tasks/{task_id}/speech/{version_id}` | 读取当前会话的 WAV 版本 |
| GET | `/health` | 服务与连接器健康（匿名白名单） |
| GET | `/auth/me` | 当前已验证身份（role/username/user_id） |
| GET | `/meta/client-capabilities` | 普通页所需生命周期、TTS 和语音状态 |
| GET | `/meta/capabilities` | 8 个工具契约、TTS 状态与安全运行配置 |
| GET | `/developer/logs` | 最近最多 200 条内存脱敏日志 |
| GET/PUT | `/admin/settings` | 读取或保存不含密钥的桌面设置 |
| GET | `/admin/restart-status` | 查询自动重启和回滚状态 |
| POST | `/admin/knowledge/reindex` | 手动重建知识索引 |
| POST | `/admin/notifications/test` | 发送一条 Windows 测试通知 |
| GET | `/voice/status` | 麦克风与转写状态 |
| GET | `/voice/devices` | 本机输入设备列表 |
| POST | `/voice/recordings` | 开始一条内存录音 |
| POST | `/voice/recordings/{id}/stop` | 停止并转写，返回文本 |
| POST | `/voice/recordings/{id}/cancel` | 取消并立即释放 PCM |

身份与数据归属全部来自已验证的若依令牌：请求经 `Authorization: Bearer` 携带 JWT，服务端验签并核对若依 Redis 会话后，以 `userId` 作为数据归属键（`user:{userId}`）。`X-Agent-Role`、`X-Session-Id` 和请求体中的角色/会话值不会被信任。任务审计、管理接口、完整能力信息、最近日志、Swagger 和 OpenAPI 都要求 developer/admin 角色；`/meta/capabilities` 不返回模型密钥或其他秘密值。除 `GET /health` 与页面静态资源外，未认证请求一律 401（稳定码 `auth_required`）。

## 5. 风险与确认

- R0：只读低风险，例如知识查询，可直接执行。
- R1：普通本地操作，根据动作语义执行。
- R2：涉及授权文稿读取或显著影响，必须人工确认。
- R3：不可逆或批量删除，必须明确确认；拒绝会取消任务并写入审计。

默认 `AGENT_FILE_OPEN_ENABLED=false`，因此文件页可以完整验证搜索、候选和确认链，但不会真的调用系统打开文件。

## 6. ZipVoice 播放

完成任务后，如果结果包含可朗读文本且 `TTS_PROVIDER=zipvoice`，结果下方显示音色下拉框和三个图标按钮：

- “音色”：从 `ZIPVOICE_VOICES` 中选择参考音色；切换后下一次播放会生成所选音色的新版本。
- `▶`：首次点击时生成 WAV 并播放；已经生成时直接重播当前版本。
- `■`：停止浏览器播放并回到音频开头，不改变 Agent 任务状态。
- `↻`：重新合成一个新版本并立即播放。

TTS 只读取完成结果中的 `answer`、`text`、`message` 或输出摘要，不读取模型思考过程和隐藏提示。音频按任务会话隔离，默认每个任务保留最近三个版本。浏览器负责播放，所以运行 Agent 的设备没有声卡时也可以在访问操作台的电脑上听到声音。

## 7. 设置与按键说话

- 在“设置”页选择 `mock` 或 `ollama`；选择 Ollama 时必须使用已发现的本机模型。
- 文件打开默认关闭。启用后仍只允许授权目录中的现有文件，多候选必须在确认页明确选择。
- 知识库目录变更后点击“重建知识索引”，页面会显示扫描和更新数量。
- ZipVoice 可编辑四个音色的 ID、名称、参考 WAV 和逐字文本；ID 必须唯一，WAV 必须为单声道 PCM16/PCM24。
- 麦克风启用后，在“通用任务”按住麦克风图标说话，松开转写；取消按钮会放弃录音。转写结果只回填输入框，确认无误后再提交任务。
- 录音前会停止正在播放的 TTS。同一时间只允许一条录音，最长默认 30 秒，原始 PCM 不落盘。
- 保存前会验证模型和目录；保存采用原子替换并保留最近 5 份 `.env` 备份。API 密钥不显示、不读取、不覆盖。

## 8. 已知边界

- Mock 模式的知识召回结果可能不如生产级 Embedding 精确；来源和链路仍可用于验证。
- 文本模块只生成内容，不包含邮件、聊天或其他发送连接器。
- 会议纪要只接受授权目录中的 `.txt` 或 `.md` 文件。
- 真实 RKLLM、NPU、温控和长稳结果必须按 `deployment/rk3588/acceptance-checklist.md` 在目标硬件验证。
- ZipVoice 当前为整段 WAV 生成，不是流式 TTS；首次播放包含模型加载时间，RK3588 RTF 尚未验证。
- `lfm2.5-thinking:1.2b` 在“把你好翻译成英文”上会生成未闭合思考过程；安全门禁会拒绝该结果，当前建议桌面默认使用 `qwen2.5:3b`。
- 文件打开回执只能确认 Windows Shell 接受请求，默认应用的窗口是否实际可见需要用户目测。
- 本轮未实现会议录音转写、唤醒词、Vosk 常驻监听、托盘、开机自启动或 Windows 安装包。
