## 1. 背景与需求

软件（agent_platform）后续要部署到 RK3588 板上，通过老板提供的公网 IP 直接对外提供访问（大概率无域名、不备案）。当前软件的访问模型是"免登录普通任务页 + 密码解锁开发者控制台"，不具备面向公网的认证能力，直接暴露等于未认证裸奔。

老板的决策：基于若依（RuoYi）做账户分离——所有访问必须先通过若依的账户验证，才能使用软件。

"账户分离"的含义（2026-08-20 已向老板确认，见第 8 节问题 6）：

1. 账户体系与业务软件分离：账号、密码、角色全部存若依（MySQL），agent_platform 不保存任何密码，只验证若依签发的令牌（JWT）。
2. 数据按账号隔离：每个账号拥有独立的业务数据空间（待办、日程、知识库等互相不可见）；同一账号跨设备登录，数据跟随账号。

## 2. 目标架构

```
公网用户
   │ HTTPS (443，唯一公网入口)
   ▼
板子（RK3588，公网 IP 或经路由器映射）
   ├── Nginx ─── 唯一对外端口
   │     ├── /            → 若依前端（登录页、账号管理）
   │     ├── /prod-api/   → 若依后端（JDK 17 + MySQL + Redis）
   │     └── /agent-api/  → agent_platform FastAPI（JWT 校验，未认证一律 401）
   └── 防火墙：除 443 外全部拒绝；SSH 仅内网或密钥 + 非常规端口
```

计算资源分配（板上）：LLM（RKLLM）→ NPU；ASR（whisper.cpp）、TTS（ZipVoice）、FastAPI → CPU；若依全家桶 → CPU，约占 1～1.5GB 内存。8G 板子放不下若依全家桶 + LLM，需按第 8 节确认板子内存后再定若依是否挪云。

## 3. 已冻结的关键决策

新会话不要重新讨论这些结论，只执行；如确需推翻，先在 TASK.md 里记录理由。

| 决策点 | 结论 |
|---|---|
| 若依版本 | RuoYi-Vue（前后端分离版，https://gitee.com/y_project/RuoYi-Vue），`springboot3` 分支 + JDK 17 + Vue2 前端（ruoyi-ui）。**不用**老板原链接的传统版（Shiro + 服务端渲染，无法与 FastAPI 对接）。用最新版（老版本有已知 CVE） |
| 若依源码 | 当黑盒使用，只改配置，不改其 Java 源码 |
| 令牌传递 | 请求头 `Authorization: Bearer <jwt>`；签名算法默认 HS512，密钥配在若依 `token.secret`（Phase 2 以实际源码核实为准） |
| 校验策略 | FastAPI 侧两步校验：① PyJWT 验 HS512 签名 + 有效期；② 查若依 Redis（key 前缀 `login_tokens:`）确认会话仍存在。第二步保证"若依里禁用账号 → 立即失效"，不依赖等 token 过期 |
| 白名单 | 仅 `/health`（及等价健康探测）。其余接口（含 SSE、语音、文件、设置、Swagger 文档）未认证一律 401 |
| 匿名访问 | 取消现有"免登录普通任务页"模型：任何人（含普通用户）必须先登录。这是对 PROJECT.md 现有描述的正式变更，Phase 0 立项时同步修订 |
| 角色映射 | 若依角色 → 现有两级界面：`普通用户角色` → user 模式；`developer`（或 admin）角色 → 开发者控制台。现有"环境变量开发者密码门"退役，由若依角色替代 |
| 密钥管理 | `token.secret` 等所有密钥走环境变量/仓库外配置，绝不进 Git（仓库既有铁律） |
| 访问方式 | 直接 IP 访问，无域名，暂不涉及 ICP 备案。HTTPS 证书：首选支持 IP 的证书机构（如 ZeroSSL，实施时核实时点政策），备选自签证书（接受浏览器警告）。（2026-08-20 已选定自签路线，见第 8 节问题 10） |
| 明文底线 | 不允许用 HTTP 明文顶替 HTTPS |
| 证据分级 | PC 完备 ≠ 板端验收（Phase 6 为止是 PC 证据；板端内存/性能/公网连通性只在 Phase 7 验收） |

## 4. 分阶段实施计划

### Phase 0：立项（0.5 天）

1. 与老板确认第 8 节问题清单的答案，回填本文档。
2. 从 `main` 新建分支。
3. 新建 `.ai-team/TASK.md` 写入：目标（公网访问前的认证网关）、验收标准（第 7 节安全清单）、非目标（不改若依源码、不开放注册、不做计费/多租户、不承诺板端性能、本任务不包含把监听地址改为非回环的 PC 行为变更——PC 开发全程回环）。
4. 修订 `.ai-team/PROJECT.md` 中"免登录普通任务页 / 开发者密码"相关描述（本任务变更了该模型）。
5. TASK.md 与代码同分支同 PR（仓库规矩：合并的 commit 是唯一交接快照）。

**验收**：TASK.md 评审通过，问题清单答案回填。

### Phase 1：本地跑通若依，玩熟（1～2 天）

PC 安装：JDK 17、MySQL 8、Redis（Windows 版，如 tporadowski/redis 或 WSL）、Node.js 18+。

步骤：

1. `git clone https://gitee.com/y_project/RuoYi-Vue.git`，切 `springboot3` 分支。
2. MySQL 建库 `ry-vue`，导入 `sql/` 下主 SQL 和 quartz SQL。
3. 配置 `ruoyi-admin/src/main/resources/application-druid.yml`（数据库连接）与 `application.yml`（Redis 地址、`token.secret`、`token.expireTime`）。**此时就生成一个强随机 secret，存入环境变量思路，为 Phase 3 复用做准备**。
4. 启动后端（`RuoYiApplication`，默认 8080）；前端 `ruoyi-ui` 下 `npm install && npm run dev`（默认 80 端口，可改）。
5. admin 登录 → **立即改默认密码** → 建"普通用户""developer"两个角色 → 各建一个测试账号。
6. F12 开发者工具 → Network → 登录一次，找到响应里的 token 和后续请求的 `Authorization: Bearer` 头，肉眼确认 token 形态（三段式 JWT）。

**验收**：能在若依界面建用户/分角色；能在 F12 看到 Bearer token。
**常见坑**：MySQL 8 时区/驱动、Redis 未设密码导致连接失败、Node 版本过低导致前端构建报错、80 端口被占用改 vue.config.js。

### Phase 2：摸清令牌机制，冻结对接契约（1～2 天）

阅读若依源码（只读不改），核实并写入契约文档 `docs/contracts/auth-gateway.md`：

1. `com.ruoyi.framework.web.service.TokenService`：确认签名算法（预期 HS512）、`token.secret` 配置项路径、过期时长（预期默认 720 分钟）与自动续期行为（临近过期会刷新，影响"禁用即时生效"的测试方法）。
2. 确认 JWT claims 结构：预期含 `login_user_key`（uuid，用于拼 Redis key）与用户名字段（版本有差异，以源码为准）。
3. 确认 Redis：key `login_tokens:{uuid}`，value 为 LoginUser 的 JSON（含用户名、角色、权限集合）。
4. 确认前端令牌存储位置（预期 cookie `Admin-Token`），Phase 4 要用。
5. 契约内容：请求头格式、白名单、401 响应格式、用户名/角色提取路径、密钥与 Redis 地址的环境变量名（建议 `RUOYI_JWT_SECRET`、`RUOYI_REDIS_URL`）。

**验收**：契约文档定稿并评审；用 `jwt.io` 或 Python 手动解码一个真实 token 验证理解正确。

### Phase 3：FastAPI 闸机中间件（3～5 天，核心开发）

1. 依赖：`PyJWT`（验 HS512）；Redis 客户端复用现有依赖或新增。
2. 实现 `agent_platform` 内的认证依赖（FastAPI dependency 或中间件）：
   - 解析 `Authorization: Bearer <jwt>` → PyJWT 验签 + 验 exp → 取 `login_user_key` → Redis 查 `login_tokens:{uuid}` 存在性 → 从 value JSON 提取用户名与角色。
   - 全部路由默认纳入校验，白名单仅 `/health`。SSE、语音、文件、设置、Swagger 一律在门后（PROJECT.md 现有不变量本就要求文档/审计在开发者会话后，本任务收紧为"一切在登录后"）。
   - 非法/缺失/过期/被吊销统一 401。
3. 会话映射：数据按账号隔离（第 8 节问题 6 答案）——令牌验证通过后以用户名作为数据归属身份接入现有会话隔离体系；HttpOnly Cookie 会话建立发生在令牌验证通过之后，同一账号跨设备登录指向同一数据空间。
4. 开发者控制台入口改为判断若依角色（developer/admin），替换现有环境变量密码门；删除或封存旧门相关代码与文档描述。
5. 配置：`RUOYI_JWT_SECRET`、`RUOYI_REDIS_URL` 走环境变量；本地开发与测试环境通过 `.env`（不入库）或测试夹具注入。**不提供生产可用的"关闭认证"开关**；测试用 Mock 而非开关。
6. 测试（进 `tests/` 常规体系）：
   - Mock 签发器（HS512 签名 + 假 Redis）覆盖：合法 token 放行、缺失 401、伪造签名 401、过期 401、Redis 中已吊销 401。
   - 角色映射：普通角色看不到开发者接口，developer/admin 可以。
   - 白名单：`/health` 无 token 可访问。
7. 全量回归：`pytest` 全绿 + `compileall` + `node --check`（仓库命令基线）。

**验收**：全部测试通过；用 curl 实测本地：无 token → 401，带真实若依 token → 200。

### Phase 4：前端登录对接（2～3 天）

1. 本地开发用代理把若依前端与 agent_platform 前端置于同一源（同源才能读 `Admin-Token` cookie）。
2. 操作台页面启动逻辑：读不到有效 token → 跳转若依登录页；登录后回跳，取 `Admin-Token`，后续所有 API 请求统一附加 `Authorization: Bearer` 头。
3. 界面按角色渲染：普通用户隐藏控制台入口。
4. 登出处理：清理本地 token 与会话，回到登录页。

**验收**：本地完整走通"未登录被拦 → 若依登录 → 进操作台用 AI 功能 → 登出"。

### Phase 5：本地全链路联调（2～3 天）

1. Windows 装 Nginx，按第 2 节架构配三条 location（`/` → 若依前端静态或 dev 代理、`/prod-api/` → 8080、`/agent-api/` → FastAPI）。
2. 浏览器只走 Nginx 入口，按剧本验收并留证（截图/录屏，存 `docs/tasks/` 本任务记录或 `evaluation/reports/`，标注为 PC 证据）：
   - 未登录访问任何 agent-api → 401/跳登录。
   - 普通用户：AI 功能可用，控制台不可见，直调开发者接口 403/401。
   - developer 用户：控制台可用。
   - 若依后台禁用该账号 → 重新请求立即 401（验证 Redis 吊销路径）。
   - 伪造 token → 401。
3. 此剧本直接复用为 Phase 7 板端验收表模板。

**验收**：剧本全绿，证据归档。

### Phase 6：部署包产出（2～3 天）

交付物（`deployment/` 下新目录，如 `deployment/ruoyi-gateway/`）：

1. `nginx.conf` 最终配置（443 + 三条转发；含限流片段）。
2. systemd unit ×3：`ruoyi.service`（JDK 17 启动 jar）、`agent-platform.service`、nginx 依赖顺序与开机自启。
3. 安装脚本：JDK/MySQL/Redis ARM64 安装与初始化、SQL 导入、环境变量写入模板（提示部署人填强随机值）。
4. 证书脚本：自签证书 openssl 一键脚本（证书路线已确定为自签，见第 8 节问题 10，不再核实 ZeroSSL/acme.sh 政策）。
5. 《部署手册》：裸机板子 → 可访问的每一步命令，面向不懂原理的执行者。
6. 《安全验收清单》：第 7 节五条，每条附验证方法（如外网 `telnet` 22 端口应不通、默认账号已改、验证码已开）。

**验收**：部署包内文档走查通过（找个没参与开发的人按手册在干净环境/虚拟机试装更佳）。

### Phase 7：板端部署与验收（老板执行，开发者远程支援）

1. 部署人按手册执行，按安全清单逐项打勾留证据（截图/命令输出）。
2. 验收表（复用 Phase 5 剧本 + 板端专项）：
   - 公网可达：外网设备访问 `https://IP` 出登录页。
   - 端口收敛：外网扫描仅 443 开放。
   - 认证闭环：登录后 AI 功能可用；禁用账号立即失效。
   - 资源实测：`free -h` 记录若依 + 全栈内存占用，确认与 LLM 并存不 OOM。
   - 持久性：重启板子后三个 systemd 服务自动恢复。
   - 冒烟：一次完整"语音输入 → 任务 → TTS 播放"带认证链路。
3. 全部通过后本任务在 TASK.md 标记 `done`，证据归档。

## 6. 风险与预案

- **若依版本 CVE**：只用最新版；部署后关注更新。
- **家宽封 80/443**：若第 8 节确认是家宽且端口被封，改用非常规端口（如 8443），Nginx 监听与手册同步改；完全不可行则升级为"云服务器入口 + frp"方案（架构不变，多一个组件）。
- **8G 板子内存不足**：若依挪便宜云服务器（2C2G 起步），板上只跑 AI 服务，需增加 frp；此为部署形态变更，不影响 Phase 3～6 的 PC 开发内容。
- **证书政策变化**：ZeroSSL 等对纯 IP 发证的支持随时间变化，Phase 6 实施时重新核实；兜底自签。
- **token 自动续期干扰吊销测试**：Phase 2 核实若依续期阈值后再写 Phase 5 的"禁用立即生效"测试步骤（例如用短 expireTime 配置或直接删 Redis key）。
- **返工主因**：跳过 Phase 2 直接写代码。契约先行。

## 7. 安全验收清单（最终门禁，五条缺一不可）

1. HTTPS：公网访问强制加密；无明文 HTTP 通道。
2. 端口收敛：防火墙仅放行 443；FastAPI/SSH/MySQL/Redis/Ollama/RKLLM 端口外网不可达；服务尽量只监听 127.0.0.1。
3. 默认账号已改：admin/admin123 不存在；若依为最新版。
4. 防爆破：若依验证码 + 登录失败限制开启；Nginx 限流生效。
5. 闸机纵深：绕过 Nginx 直连 FastAPI 端口时，无有效 token 仍全部 401。
