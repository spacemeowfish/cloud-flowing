# Qwen 准确率与 T4 加固任务记录

- 状态：PC/Ollama 范围已完成；等待 RK3588 真机复测
- 日期：2026-08-02
- 基线：非 Git 工作区；真实 Qwen2.5:3b 固定 60 条端到端通过率 73.33%

## 目标

1. 修复 `text_polish` 的 `summarize` 未初始化草稿变量问题，并覆盖四种真实文本操作。
2. 在不改变工具、权限、确认和审计边界的前提下，把一次全量意图/参数生成改为高置信预路由与单意图参数抽取；只有未命中预路由时才先调用意图分类。
3. 对有效 JSON 但不符合当前阶段 Schema 的输出最多执行一次受限修复，不接受任意文本、不放宽 Schema。
4. 使用失败用例形成 `meeting/file`、`reminder/todo/schedule` 对比提示。
5. 固定 60 条评测集，记录数据集摘要、Provider、模型名、模型摘要、提示版本和每例模型调用轨迹，支持同集 A/B。

## 非目标

- 不做 LoRA、SFT 或更换模型。
- 不改变 R2/R3 确认策略，不让模型直接执行工具或决定权限。
- 不把确定性预路由扩展为自然语言参数解析器。
- 不声称 Windows/Ollama 结果等同 RK3588/RKLLM 真机结果。

## 已确认问题

- `text_processing_tool.py` 的 `summarize` 分支未给 `draft` 赋值，真实执行稳定抛出 `UnboundLocalError`。
- 旧的详细评测使用无副作用 `DryRunTool`，能够验证执行链和策略，但不会执行生产 `TextProcessingTool`，因此没有发现该问题。
- 2026-08-02 真实 Qwen2.5:3b 60 条基线：意图/工具 85.00%，Schema 90.00%，语义匹配 76.67%，端到端 73.33%。错误集中在提醒/待办/日程边界、会议路径与跨工具字段串扰。

## 架构不变量

1. 预路由只选择意图，不生成工具参数；未命中时必须使用模型分类。
2. 参数抽取只接收所选意图的模型接受 Schema，其他工具字段必须被拒绝。
3. 只有完整 JSON 对象违反 Schema 时才能修复；语法错误、截断、多对象和解释文字继续失败。
4. 修复最多一次，第二次失败立即返回错误；修复仍经过完全相同的 Schema 校验。
5. 参数规范化、工具严格 Schema、Policy、确认和执行顺序保持不变。
6. 事实保留优先于摘要目标长度；所有非发送文本操作统一返回 `【草稿】`。

## 验收条件

- 四种文本操作各至少三个真实工具用例；`summarize` 经 `AgentCore -> ToolExecutor -> TextProcessingTool` 集成通过。
- 预路由高置信边界和未命中模型分类均有测试。
- 参数阶段 Schema 不包含其他意图字段；Schema 修复成功、二次失败、不修复非法 JSON均有测试。
- Mock 和 RKLLM 协议模拟固定 60 条继续通过。
- 全量 `pytest` 通过；真实 Qwen 使用同一 60 条生成新的报告和 raw JSONL。
- 新 raw 快照包含模型摘要、提示版本、数据集摘要、路由来源、模型调用次数和是否修复。
