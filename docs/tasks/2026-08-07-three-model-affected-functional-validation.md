# 三模型受影响功能复测

- 状态：已完成
- 日期：2026-08-07
- 基线：`main` / `ebc208f` (`fix: make CLI installation self-contained`)
- 前置任务：[`2026-08-06-local-functional-hardening.md`](2026-08-06-local-functional-hardening.md)

## 目标

在本地功能硬化完成后，通过 Ollama 原生适配器分别接入三个实际安装的模型，重新验证会受到自然语言理解、参数抽取或文本生成影响的功能，并生成可复现报告。模型评测与真实工具执行必须分开，不能把模型输出错误、环境错误和工具缺陷混为一类。

## 范围与安全边界

- 模型：`qwen2.5:3b`、`qwen3:1.7b`、`lfm2.5-thinking:1.2b`。
- 固定评测：60 条，使用临时数据库和 dry-run 工具，不产生真实副作用。
- 功能流程：知识、文件、提醒、待办、日程、文本、会议，共 7 类；每个模型使用独立临时数据库、授权根、知识目录和会议输出目录。
- 真实文件打开保持关闭；候选确认只验证 `disabled_by_configuration` 回执。
- 不验证 Windows toast 实际弹出、音频链路、RK3588/RKLLM、云模型和多用户并发。
- 不停止用户的 Ollama 守护进程和现有 8000 mock 服务，不修改 `.env`，不清理用户数据。

## 架构不变量

- 模型只负责意图、参数和文本草稿；Schema、权限、确认、持久化、删除、审计和工具执行继续由确定性模块负责。
- 模型报错或给出不可信 `missing_fields` 时，系统必须停在失败/缺字段状态，不能自动越过确认执行。
- 模型功能通过必须以最终业务结果为准，不能只看任务状态为 `completed`。

## 实施与发现

新增 `scripts/validate_three_model_affected.py`，用于逐模型执行隔离业务流程并保存原始任务状态、参数、结果和严格功能判定。

复测暴露出“清空全部提醒”未被现有归一化规则覆盖。已在 `agent_platform/core/parameter_normalizer.py` 增加该中文变体，并在 `tests/test_parameter_normalizer.py` 增加回归断言。确定性控制项通过，但真实模型仍可能把可选字段误报为缺失字段，因此报告继续把模型路径判为未通过，未通过确认接口强制越过安全停点。

## 遗留风险

- 固定 60 条评测没有覆盖“清空全部提醒”的精确说法；当前有回归测试和真实隔离证据，但后续应加入固定模型集。
- `missing_fields` 是模型输出，当前会被安全地视为需要用户补充；小模型误报会降低可用性。后续应在不放宽必填字段的前提下，用工具 Schema 对模型缺字段声明做确定性裁决。
- 日程的 `range_end`/`end_text` 混淆和 LFM 日期丢失仍需参数归一化或模型专用提示修复。
- LFM 文本结果虽保留金额/电话等事实，仍可能泄露占位符或产生不可读摘要，必须增加结果质量门禁和回退。
- 本轮 P50/P95 是已加载模型的单次结构化调用延迟，不是冷启动、token/s、整任务耗时或单模型独占资源性能。
