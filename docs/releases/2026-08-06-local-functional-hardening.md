## 1. 结论摘要

这次反馈的问题主要不是“必须运行大模型才能工作”，而是三类本地实现缺陷叠加：

1. 服务从其他目录启动时，相对资源路径指向了空目录，导致知识、文件和会议路径全部失效。
2. mock 适配器和参数归一化没有把自然语言命令拆成稳定的业务参数，提醒、待办、日程和文本处理因此出现内容污染或错误分支。
3. 后端虽然返回了结构化记录，但操作台只展示摘要或裸 ID，用户无法直接辨认和操作记录。

修复后，mock 模式可以独立完成知识检索、文件候选检索、提醒、待办、日程、确定性的文本处理、会议纪要和通用任务路由；不依赖 Ollama、RKLLM 或云端模型。高风险动作仍按既有 R2/R3 确认策略执行。

```powershell

```

Windows 安装包包含 `winotify`；若环境仍缺少它，通知适配器会退回控制台输出，但建议重新执行安装命令，避免调用旧目录中的全局 CLI。启动后打开 `http://127.0.0.1:8000/`。
